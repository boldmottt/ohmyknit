| 문제 | 왜 문제였나 | 고친 방식 |

| 중간 실측이 "조정할까요?"만 묻고 끝남 | 무엇을 하면 되는지 모름 | "목표 길이까지 N단 필요, 약 M단 더"처럼 알려 주고, 실측 게이지를 넣은 채 재변환 화면으로 연결 |
| 그 밖 | | 형식이 틀린 진행 기록 거부, 실 무게·완성 전에 진행 먼저 전송, 팔레트 색을 지우면 차트 번호 정리, 시뮬레이션에서 0단으로 끌기, 터치로 끌 때 화면이 같이 스크롤되지 않게, 기기 저장소를 못 쓸 때 바로 전송 |

**검토했지만 그대로 둔 것 (알아 둘 점)**

- 두 기기의 시계가 다르면 이벤트 순서가 실제와 조금 다를 수 있어요. +1/−1은 순서와 상관없이 합쳐지고, "N단으로 이동"만 영향을 받아요.
- 타이머는 화면을 다시 불러오면 0부터 다시 세요. 속도·남은 시간은 서버가 기록으로 계산해서 영향이 없어요.
- 이미 시작한 조각의 남은 단 수를 자동으로 고쳐 주지는 않아요. 몇 단을 더 뜰지는 조언으로만 알려 줘요.
- 터치로 끌어서 진행 위치를 바꾸는 동작은 실제 아이패드에서 한 번 확인이 필요해요 (여기서는 마우스로만 확인).

**실 라이브러리 참고**: 기본 색 견본(48색)은 색 고르기용으로 만든 것이고 실제 판매 제품의 색 데이터가 아니에요. 가지고 있는 실은 "내 실 등록"으로 사진과 함께 넣어 주세요.

## Part 1. PRD (제품 요구사항 정의)

### 1.1 배경과 문제

뜨개질하는 사람들은 보통 도안을 사서 뜨거나 AI에게 도안을 받아서 뜹니다. 그런데 도안에 적힌 게이지는 도안 작가의 손 기준입니다. 손이 쫀쫀한 사람(쫀손)이 도안대로 뜨면 완성품이 작게 나오고, 이 사실은 대부분 다 뜬 뒤에야 알게 됩니다. 기존 앱들은 이 문제를 각각 일부만 다룹니다. 차트 에디터(knithub 등)는 디자인에만 집중하고, 단 카운터 앱은 숫자만 세며, 게이지 계산기는 일회성 계산만 해 줍니다.

### 1.2 제품 비전

"도안을 내 손에 맞게 바꿔 주고, 뜨는 과정을 옷장 속 옷처럼 지켜보게 해 주는 나만의 뜨개 작업실"

### 1.3 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | 아내분 (주 사용자) |
| 뜨개 경력 | 중급. 스웨터, 배색 작품 가능 |
| 도안 경로 | 구매한 PDF 도안, AI 생성 도안 |
| 핵심 불편 | 쫀손이라 완성품이 작게 나옴. 여러 작품을 동시에 뜨다 보면 어디까지 떴는지 헷갈림 |
| 사용 환경 | 소파에서 뜨면서 아이패드나 아이폰을 옆에 둠. 손이 바빠서 화면을 자주 만지기 어려움 |
| 보조 사용자 | 남편(개발자, 관리자). 두 번째 프로필 |

### 2.1 전체 아키텍처

```
┌────────────── 맥북 (항상 켜 둠, 전원 연결) ──────────────┐
│                                                         │
│  wrangler dev --persist-to ./data                       │
│  ┌──────────────── Worker (Hono) ────────────────┐      │
│  │  /api/*  REST API                             │      │
│  │  /*      정적 프론트엔드 (Vite 빌드 결과)       │      │
│  └──────┬───────────────┬────────────────┬───────┘      │
│         │               │                │              │
│     D1 (SQLite)     R2 (파일)      AI 호출 (외부 LLM API) │
│     ./data/d1       ./data/r2      도안 파싱·생성        │
│                                                         │
│  cloudflared (Tunnel) ── 외부 접속 경로                  │
│  백업 스크립트 (launchd, 매일 03:00) → iCloud/외장 디스크  │
└─────────────────────────────────────────────────────────┘
              │
     Cloudflare Access (이메일 인증)
              │
   ┌──────────┼───────────┐
 맥북 브라우저  아이패드     아이폰
               (PWA 설치, IndexedDB 오프라인 캐시)
```

### 2.2 기술 스택

| 계층 | 선택 |
|---|---|
| 프론트엔드 | React 19 + Vite + TypeScript |
| 상태 관리 | Zustand(UI 상태) + TanStack Query(서버 상태) |
| 애니메이션 | Motion (옷장 문, 패널, 화면 전환) |
| 그래픽 | PixiJS v8 (옷 천 물리, 니트 시뮬레이션), Canvas 2D (차트) |
| 오프라인 | Service Worker(Workbox) + Dexie(IndexedDB) |
| 백엔드 | Hono on Cloudflare Workers |
| DB / 파일 | D1 / R2 (로컬 영속) |
| ORM | Drizzle ORM (D1 지원, 마이그레이션 관리) |
| 테스트 | Vitest(게이지 엔진), Playwright(주요 흐름) |

### 2.3 로컬 운영 시 꼭 챙길 점

- **맥북 잠자기 문제**: 맥북이 잠들면 Tunnel도 끊겨서 아이패드에서 접속할 수 없습니다. 그래서 두 겹으로 대응합니다. 첫째, 전원 연결 시 잠자기 방지를 설정합니다(시스템 설정의 배터리 옵션 또는 caffeinate). 둘째, 작업 화면은 오프라인 우선으로 만들어서 서버가 끊겨도 카운터는 계속 동작하고, 변경분은 큐에 쌓였다가 재연결 시 동기화되게 합니다.
- **데이터 위치 고정**: `--persist-to ./data`로 저장 경로를 명시해서 프로젝트 폴더 밖 임시 경로에 데이터가 흩어지지 않게 합니다.
- **백업**: `wrangler d1 export --local`로 SQL 덤프를 만들고, `./data/r2`를 압축해서 하루에 한 번 iCloud Drive나 외장 디스크로 복사합니다. 이 과정은 launchd로 예약합니다. 최근 30일치를 보관합니다.
- **AI API 키**: `.dev.vars`에 두고 git에서 제외합니다.

## Part 4. 핵심 알고리즘

> 구현: [`packages/gauge-engine`](../packages/gauge-engine) — 아래 예시 숫자가 모두 단위 테스트로 들어가 있습니다.

### 4.1 콧수 변환 (반복 단위 보존)

```
k_st = 내 코 게이지 / 도안 코 게이지        # 예: 25 / 22 = 1.136
raw  = 도안 콧수 × k_st                    # 200 × 1.136 = 227.3
if 배색 반복 단위 R:
    후보 = R의 배수 중 raw에 가장 가까운 값  # R=12 → 228 (12×19)
    완성 치수 오차 = |후보 − raw| / 내 코 게이지 × 10cm  → 사용자에게 표시 (0.29cm)
else:
    후보 = 짝수/구조 조건에 맞춰 반올림
```

오차가 여유분 허용치(기본 ±1.5cm)를 넘으면 바늘 교체 방식을 함께 제안합니다.

### 4.2 단수와 늘림·줄임 재분배 (v1.0.1 수정)

도안: "6단마다 1회 늘림(2코) × 12회" = 72단 동안 24코 늘림.

내 게이지: 코 25/22 (k_st = 1.136), 단 33/30 (k_row = 1.1)

1. **단 수**: 72 × 1.1 = 79.2 → **79단**
2. **늘림 횟수** (v1.0에서 빠졌던 단계): 늘어나는 폭도 내 코 게이지로 바꿔야 합니다. 24 × 1.136 = 27.3코 → 한 번에 2코씩이니 27.3 / 2 = 13.6 → **14회 (28코)**
   - 횟수를 12회로 그대로 두면 24코만 늘어나서, 내 게이지로는 원래 폭보다 약 1.3cm 좁아집니다.
   - 시작 콧수를 반복 단위 배수로 맞췄다면, 늘림 후 콧수도 반복 단위 조건을 다시 확인합니다.
3. **간격 재분배**: 79단에 14회

```
n = 14,  R' = 79
base = floor(79 / 14) = 5,  r = 79 mod 14 = 9
→ 6단 간격 9회 + 5단 간격 5회   (6×9 + 5×5 = 54 + 25 = 79 ✓)
배치: 긴 간격과 짧은 간격을 번갈아 고르게 섞음 (Bresenham 방식)
```

결과는 사람이 읽기 쉬운 문장으로 바꿔서 rowTable에 넣습니다. 예: "6단마다 늘림 9회, 5단마다 늘림 5회 (번갈아)".

### 4.3 진척도

```
조각 진척도 = (Σ 완료한 단의 콧수 + 현재 단에서 뜬 코) / 조각 총 콧수
전체 진척도 = Σ 조각별 뜬 코 / Σ 조각별 총 콧수
```

### 4.4 손 보정 계수 학습

```
스와치 기반:   k_swatch = 스와치 게이지 / 도안 게이지 (블로킹 후 값 우선)
완성 실측 반영: k_actual = (변환 후 예상 치수 / 실제 완성 치수) × k_used
갱신:          k_new = (k_old × n + k_actual × w) / (n + w)   # 완성 실측 가중치 w=2
```

예: k_used 1.136으로 떠서 예상 96cm였는데 실제 92cm → k_actual = 96/92 × 1.136 ≈ 1.185 (더 쫀쫀함 → 다음엔 코를 더 잡음).

스와치보다 완성 실측을 더 신뢰하는 이유는, 큰 작품을 뜰 때와 스와치를 뜰 때 손 텐션이 다른 경우가 많기 때문입니다.

## Part 5. 화면 E: 작업 화면 상세 설계 ★

> 참고: knithub의 "왼쪽 차트 + 오른쪽 니트 미리보기" 구성 ([스크린샷](reference/knithub-chart-editor.png)). 화면 E는 여기에 **진행 상태(뜬 부분/현재 단/고스트)** 와 **카운터 도크**를 더한 형태입니다.

### 5.1 설계 원칙

사용자가 가장 오래 머무는 화면이고, 사용하는 동안 두 손은 바늘을 잡고 있습니다. 그래서 다음 다섯 가지 원칙을 지킵니다.

1. **눈으로 보는 시간은 최소, 손으로 만지는 시간은 거의 0.** 1~2m 떨어져서도 현재 단과 지시가 읽혀야 합니다.
2. **하나의 진실(현재 단).** 차트, 지시 카드, 시뮬레이션, 카운터가 모두 같은 "현재 단"을 가리킵니다. 어느 곳에서 바꿔도 나머지가 즉시 따라옵니다.
3. **실수는 언제든 되돌릴 수 있음.** 모든 조작은 이벤트로 기록되고, 실행 취소가 됩니다.
4. **장식은 옷장에서, 작업 화면은 읽기 위주.** 스킨은 테두리와 종이 질감 정도로만 적용하고, 차트 가독성을 최우선으로 합니다.
5. **다음에 할 일을 미리 알려 줌.** 늘림, 분리, 배색 변경을 놓치는 게 가장 흔한 실수입니다.

### 5.2 진입과 종료 전환

**진입 (약 0.8초)**: 상세 패널에서 이어하기를 누르면 옷걸이의 옷이 화면 가운데로 날아오면서 커지고, 옷장 배경은 어두워지며 사라집니다. 커진 옷이 그대로 가운데 시뮬레이션 캔버스가 되고(Shared element transition), 좌우에서 도안 패널과 카운터 도크가 미끄러져 들어옵니다. 마지막으로 뜬 단 위치로 시뮬레이션과 차트가 자동 스크롤됩니다.

**종료**: 좌상단 "옷장으로" 버튼을 누르면 진행 상황을 저장하고, 역방향 애니메이션으로 옷이 옷걸이로 돌아가 걸리면서 한 번 흔들립니다. 이번 세션에서 뜬 만큼 옷 텍스처가 갱신된 상태로 보이므로 "오늘 이만큼 떴다"는 성취감을 줍니다. 돌아갈 때 세션 요약 토스트("오늘 14단 · 52분 · +3.2%")를 잠깐 띄웁니다.

| 현재 단 | 밝은 테두리 + 바늘에 걸린 코 (원통뜨기는 줄바늘 곡선) |
| 남은 단 | 회색 반투명 고스트, 배색 무늬는 아주 흐리게 |
| 완성 실루엣 | 점선 외곽선, 조각 형태 (늘림·줄임 반영) |

상호작용

| 동작 | 결과 |
|---|---|
| 캔버스를 위아래로 드래그 | "여기까지" 선이 손가락을 따라 이동. 단 번호 말풍선이 따라다니고, 놓으면 "47단 → 52단으로 이동할까요?" 확인. 5단 이하 이동은 확인 없이 바로 적용하고 실행 취소 토스트 표시 |
| 휠 / 핀치 | 줌. 확대하면 코 하나하나가 보임 |
| 마우스 올리기 | 해당 단이 차트에서도 동시에 강조 (양방향 동기화) |
| 앞/뒤 토글 | 원통뜨기나 앞뒤판이 있는 경우 뒷면 표시 |

**완성본과 비교하기 (토글)**:

```
┌──────────────────────────────┐
│     완성된 스웨터 전체 실루엣    │
│   ┌────┐  ┌──────┐  ┌────┐   │
│   │ 0% │  │ 몸판  │  │60% │   │
│   │오른 │  │ 72%  │  │왼   │   │
│   │소매 │  │▓▓▓▓▓▓│  │소매 │   │
│   └────┘  └──────┘  └────┘   │
│         전체 41% 완성          │
│ 현재 길이 38cm / 목표 52cm      │
│ 남은 코 약 31,200코 · 약 18시간  │
└──────────────────────────────┘
```

조각을 하나씩 뜨는 도안은 조각들이 조립된 완성 모습 위에 진행도를 칠해서 보여 주고, 조각을 클릭하면 그 조각으로 바로 이동합니다. 탑다운 원통뜨기는 한 덩어리 실루엣으로 보여 줍니다.

**렌더링 구현**: 코 하나를 V자 스프라이트 1장으로 두고 색만 바꿔서 인스턴싱합니다. 단 단위로 컨테이너를 나누고, 진행이 바뀌면 바뀐 단만 다시 그립니다. 화면에 보이는 영역만 그리는 뷰포트 컬링을 적용합니다.

#### ③ 진행 도크

**메인 카운터**: 숫자는 최소 64px 크기로, 소파에서도 읽히게 합니다. +1 버튼은 도크 폭 전체를 쓰는 큰 버튼이고, −1은 작게 둡니다.

+1을 눌렀을 때 일어나는 일 (순서대로):

1. 화면 즉시 반영 (낙관적 업데이트), 짧은 진동(지원 기기)과 "톡" 소리(선택)
2. 차트 자석자 한 칸 위로, 시뮬레이션에 한 단 채워지는 애니메이션(200ms)
3. 지시 카드 갱신, 반복 카운터 진행
4. 이벤트 큐에 기록, 타이머가 멈춰 있었다면 자동 시작
5. 다음 단에 이벤트가 있으면 카드가 노란색으로 바뀌고 알림

**연결된 반복 카운터**: 뜨개인들이 실제로 쓰는 "보조 카운터"입니다. 메인 단수에서 자동 계산되므로 따로 누를 필요가 없습니다. 무늬 반복(차트 몇 단째), 늘림 간격(다음 늘림까지 몇 단), 사용자 정의 카운터(예: 케이블 꼬기 8단마다)를 둘 수 있습니다.

**다가오는 일**: 앞으로 20단 안의 이벤트를 시간순으로 보여 줍니다. 아이콘은 늘림·줄임 ⚠, 구조 변경(분리, 줍기, 코막음) ◇, 배색 변경 ●, 실측 체크인 📏으로 구분합니다. 이벤트 단에 도달하면 확인 체크를 해야 +1이 넘어가도록 하는 "잠금 이벤트" 옵션도 둡니다. 소매 분리처럼 놓치면 크게 풀어야 하는 단계에 쓰입니다.

**도구 버튼**:

| 버튼 | 동작 |
|---|---|
| 📏 실측 | 현재 길이나 너비 입력 → 예상 치수와 비교. 오차 3% 이상이면 경고("도안 기준보다 5% 쫀쫀해지고 있어요. 남은 부분의 단수를 조정할까요?"). 결과는 손 프로필 학습 데이터로 저장 |
| 📝 메모 | 현재 단에 메모와 사진 첨부. 차트와 시뮬레이션의 해당 단 옆에 작은 핀으로 표시 |
| ↺ 풀기 | "몇 단 풀었나요?" 입력 → 단을 되돌리고 frog 이벤트로 기록(사유 선택: 실수, 게이지, 마음에 안 듦). 일반 −1과 구분해서 통계에 반영 |

#### 하단 상태 바

조각 진척도, 전체 진척도, 남은 예상 시간(최근 5회 세션의 평균 분당 코 수 기준), 실 사용량 예측(지금까지 사용한 실 무게 ÷ 뜬 코 수 × 남은 코 수, 실 무게는 중간에 저울로 재서 입력)을 보여 줍니다.

#### 상단 바

| 요소 | 설명 |
|---|---|
| 조각 탭 | 앞판, 뒤판, 소매 등. 각 탭에 작은 진행 링 표시 |
| 타이머 | 첫 +1에 자동 시작. 5분 동안 조작이 없으면 자동 일시정지하고, 그 시간은 기록에서 제외 |
| 저장 상태 | ☁ 저장됨 / ⟳ 동기화 중 / ⚡ 오프라인(N개 대기) |
| ⋯ 메뉴 | 집중 모드, 다크 모드, 화면 꺼짐 방지, 단축키 안내, 내용 수정하기, 완성 처리 |

### 5.5 집중 모드 (손이 바쁠 때)

⋯ 메뉴나 F 키로 전환합니다. 아이패드를 거치대에 세워 두고 쓰는 상황을 가정합니다.

```
┌──────────────────────────────────────────┐
│   몸판 · 72%                    ⏱ 00:52   │
│                                          │
│                 47                       │
│               / 112 단                    │
│                                          │
│   ┌──────────────────────────────────┐   │
│   │ 228코 · 버건디 2 + 핑크 1 반복      │   │
│   │ ■■▢■■▢■■▢■■▢  (현재 단 차트 한 줄)   │   │
│   └──────────────────────────────────┘   │
│                                          │
│   ⚠ 3단 뒤 늘림 8코 (마커 양옆)            │
│                                          │
│   ┌──────────── 화면 아무 곳이나 탭 = +1 ──┐│
└──────────────────────────────────────────┘
```

- 화면 아무 곳이나 탭하면 +1, 길게 누르면 −1입니다. 실수 방지를 위해 탭 사이 최소 간격(기본 1.5초)을 둡니다.
- Screen Wake Lock API로 화면이 꺼지지 않게 합니다. 최신 iPadOS Safari에서 지원되지만, 지원하지 않는 환경에서는 안내 문구를 띄웁니다.
- 다크 모드를 기본으로 해서 저녁에 눈부심을 줄입니다.

### 5.6 입력 방법

| 입력 | +1 | −1 | 기타 |
|---|---|---|---|
| 키보드 | Space, ↑ | Backspace, ↓ | N 메모, M 실측, C 비교, F 집중 모드, ⌘Z 실행 취소, 1~9 조각 탭 |
| 블루투스 페이지 터너 / 발판 | PageDown, → | PageUp, ← | 대부분 키보드 신호로 인식되므로 추가 개발 없이 매핑만 하면 됩니다. 발판을 쓰면 손을 전혀 쓰지 않아도 됩니다. 가장 추천하는 방식입니다. |
| 터치 | +1 버튼, 집중 모드 탭 | −1 버튼, 길게 누름 | |
| 음성 (P2) | "다음", "한 단" | "취소", "한 단 뒤로" | Web Speech API는 브라우저마다 지원 차이가 있어 실험 기능으로 둡니다 |

## Part 6. 새 프로젝트 마법사 (작업 화면의 입구)

옷장의 빈 옷걸이를 누르면 다섯 단계로 진행합니다.

4. **정보 입력**: 이름, 실, 바늘, 시작일
5. **옷장에 걸기**: 옷이 옷걸이에 걸리는 애니메이션과 함께 옷장으로 돌아가거나 바로 작업 시작

## Part 9. 열린 질문 (아내분과 확인할 것)

1. 주로 뜨는 방식이 탑다운 원통뜨기인가요, 조각을 떠서 잇는 방식인가요? 시뮬레이션과 비교 화면의 우선순위가 달라집니다.
2. 단 카운터를 지금은 무엇으로 쓰고 있나요(실물 카운터, 다른 앱)? 그 도구의 장단점을 들으면 도크 설계를 다듬을 수 있습니다.
3. 블루투스 페이지 터너나 발판을 써 볼 의향이 있나요? 있다면 작업 화면 경험이 크게 좋아집니다.
4. 스와치를 블로킹까지 하는 편인가요? 손 프로필 입력 항목을 정하는 데 필요합니다.
